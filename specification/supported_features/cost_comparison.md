# Cost Comparison

## Description

FOCUS supports comparing cost columns to identify savings from [negotiated discounts](#term), the impact of [commitment discount](#term) amortization, and differences between [cash-based](#term) and [accrual-based](#term:accrual-based-accounting) cost perspectives.

[Billed Cost](#col) represents the [cash-based](#term) view: amounts invoiced by the [Invoice Issuer Name](#col) in a given [billing period](#term). [Effective Cost](#col) represents the *accrual-based* view: costs recognized when [resources](#term) are consumed, [services](#term) are used, or [contract commitments](#term) are recognized. [List Cost](#col) provides the pre-discount baseline. [Contracted Cost](#col) reflects pricing after [negotiated discounts](#term).

Comparing [List Cost](#col) against [Contracted Cost](#col) quantifies [negotiated discount](#term) savings; comparing [Contracted Cost](#col) against [Effective Cost](#col) isolates [commitment discount](#term) savings; comparing [Effective Cost](#col) against [List Cost](#col) shows total combined savings. [Billed Cost](#col) and [Effective Cost](#col) diverge when billing timing differs from consumption, such as with [commitment discounts](#term) or prepaid purchases.

When comparing costs across marketplace boundaries, [practitioners](#term) should be aware that [Billed Cost](#col) is zero for [charges](#term) generated by entities not responsible for invoicing, so [Billed Cost](#col) and [Effective Cost](#col) sums may not align within a single dataset when [covering charges](#term) and [covered charges](#term) span multiple [invoice issuers](#term). This is expected and does not indicate a data quality issue. See the [Marketplace Purchases](#supportedfeatures.marketplacepurchases) supported feature, [Examples: Commitment Discount Flexibility](#appendix.examples:commitmentdiscountflexibility), and [Examples: SaaS](#appendix.examples:saas) for additional context.

## Example SQL Queries

### Discount Effectiveness by Service

```sql
WITH AggregatedData AS (
  SELECT
    ServiceProviderName,
    BillingAccountId,
    BillingAccountName,
    BillingCurrency,
    ServiceName,
    SUM(EffectiveCost) AS TotalEffectiveCost,
    SUM(BilledCost) AS TotalBilledCost,
    SUM(CASE
          WHEN ChargeCategory = 'Usage' AND BilledCost = 0 AND EffectiveCost != 0
          THEN 0
          ELSE ContractedCost
        END) AS TotalContractedCost,
    SUM(CASE
          WHEN ChargeCategory = 'Usage' AND BilledCost = 0 AND EffectiveCost != 0
          THEN 0
          ELSE ListCost
        END) AS TotalListCost
  FROM CostAndUsage
  WHERE BillingPeriodStart >= ?
    AND BillingPeriodEnd < ?
    AND ChargeClass IS NULL
  GROUP BY
    ServiceProviderName,
    BillingAccountId,
    BillingAccountName,
    BillingCurrency,
    ServiceName
)
SELECT ServiceProviderName,
    BillingAccountId,
    BillingAccountName,
    BillingCurrency,
    ServiceName,
    TotalEffectiveCost,
    TotalBilledCost,
    TotalListCost,
    (1 - TotalContractedCost / NULLIF(TotalListCost, 0)) * 100 AS ContractedDiscount,
    (1 - TotalEffectiveCost / NULLIF(TotalListCost, 0)) * 100 AS EffectiveDiscount
FROM AggregatedData
```

### Cash vs. Accrual Comparison by Billing Period

```sql
SELECT
  ServiceProviderName,
  InvoiceIssuerName,
  BillingPeriodStart,
  BillingPeriodEnd,
  SUM(BilledCost) AS TotalBilledCost,
  SUM(EffectiveCost) AS TotalEffectiveCost,
  SUM(EffectiveCost) - SUM(BilledCost) AS CostBasisDifference
FROM CostAndUsage
WHERE BillingPeriodStart >= ? AND BillingPeriodEnd < ?
GROUP BY
  ServiceProviderName,
  InvoiceIssuerName,
  BillingPeriodStart,
  BillingPeriodEnd
HAVING ABS(SUM(EffectiveCost) - SUM(BilledCost)) > 0.01
```

### Commitment Discount Savings for a Charge Period Range

For each [commitment discount](#term) within a [charge period](#term) range, compares the [Contracted Cost](#col) of the usage it covered with its total [Effective Cost](#col), including the unused portion (i.e., where [Commitment Discount Status](#col) is ["Unused"](#val:CostAndUsage.CommitmentDiscountStatus)). The difference is the net savings attributable to the [commitment discount](#term), and a negative value means the unused portion cost more than the [commitment discount](#term) saved on covered usage.

```sql
SELECT
  ServiceProviderName,
  BillingCurrency,
  CommitmentDiscountId,
  MIN(ChargePeriodStart) AS ChargePeriodStart,
  MAX(ChargePeriodEnd) AS ChargePeriodEnd,
  SUM(CASE WHEN CommitmentDiscountStatus = 'Used' THEN ContractedCost ELSE 0 END) AS TotalContractedCost,
  SUM(EffectiveCost) AS TotalEffectiveCost,
  SUM(CASE WHEN CommitmentDiscountStatus = 'Used' THEN ContractedCost ELSE 0 END) - SUM(EffectiveCost) AS CommitmentDiscountSavings
FROM CostAndUsage
WHERE ChargePeriodStart >= ? AND ChargePeriodEnd < ?
  AND ChargeCategory = 'Usage'
  AND CommitmentDiscountId IS NOT NULL
GROUP BY
  ServiceProviderName,
  BillingCurrency,
  CommitmentDiscountId
```

### Billing Period vs. Charge Period Comparison

A [billing period](#term) identifies when a [charge](#term) is invoiced, while a [charge period](#term) identifies when the [charge](#term) was incurred, so filtering the same data by each can return different totals. This query separates the [charges](#term) in each [billing period](#term) into those whose [charge period](#term) falls within the [billing period](#term) and those whose [charge period](#term) extends outside it (e.g., purchases that cover a longer term).

```sql
SELECT
  ServiceProviderName,
  BillingCurrency,
  BillingPeriodStart,
  BillingPeriodEnd,
  CASE
    WHEN ChargePeriodStart >= BillingPeriodStart AND ChargePeriodEnd <= BillingPeriodEnd
    THEN 'Within Billing Period'
    ELSE 'Outside Billing Period'
  END AS ChargePeriodAlignment,
  MIN(ChargePeriodStart) AS EarliestChargePeriodStart,
  MAX(ChargePeriodEnd) AS LatestChargePeriodEnd,
  SUM(BilledCost) AS TotalBilledCost,
  SUM(EffectiveCost) AS TotalEffectiveCost
FROM CostAndUsage
WHERE BillingPeriodStart >= ? AND BillingPeriodEnd < ?
GROUP BY
  ServiceProviderName,
  BillingCurrency,
  BillingPeriodStart,
  BillingPeriodEnd,
  CASE
    WHEN ChargePeriodStart >= BillingPeriodStart AND ChargePeriodEnd <= BillingPeriodEnd
    THEN 'Within Billing Period'
    ELSE 'Outside Billing Period'
  END
```
