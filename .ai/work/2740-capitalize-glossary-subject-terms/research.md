# Research: #2740 Capitalize glossary terms linked as the column subject

## Issue requirements

* Capitalize the linked glossary term in the column introduction to match the column display name, since the first sentence describes the column rather than the concept.
* Definition of Done: a PR fixing the Availability Zone (Cost and Usage) and Billing Currency (Cost and Usage, Contract Commitment) introductions.
* Precedent: #2567 (List Unit Price, Contracted Unit Price).

| `datasets/cost_and_usage/columns/billingcurrency.md` | 3 | `[*Billing currency*](#glossary:billing-currency)` | `[*Billing Currency*](#glossary:billing-currency)` |

`invoice_detail/columns/billingcurrency.md:3` already uses `[*Billing Currency*]`.

The first three fixes were generated by the MD992 lint rule (Display Name casing), proposed in #2759 (issue #2758). Across all 127 column files it reports only those three. The Sub Account Name fix was found during review. MD992 does not check body text, because a miscased Display Name there cannot reliably be told apart from the concept or sentence case.

## Guideline basis

* **Linked subject casing:** not written in the guidelines. The convention comes from #2567 and #2740.
* **Plain-text casing:** `editorial-guidelines.md` says references to FOCUS entities in non-normative content MUST use Display Names when available. `Sub account Name` is a miscased Display Name. It is not named in #2740 but is the same issue in the same kind of sentence.
* **Leading articles:** no rule. Intros use both forms (`The List Unit Price ...`, `A Sub Account Name is ...`, `Billing Currency is ...`), so `An` is kept in the Availability Zone intro.

## Merge order

This PR must merge before the tooling PR. Once MD992 is enabled, these four errors would fail lint on any branch that does not include the fixes.
