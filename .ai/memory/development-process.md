# FOCUS Development Process

## Feature Request Lifecycle

1. **Proposal** - People propose a feature request
2. **Prioritization** - Maintainers provide effort/impact analysis to prioritize features
3. **Selection** - Maintainers select the top features for inclusion in the next release
4. **Assignment** - FOCUS PM identifies owners for each feature request
5. **Drafting** - Owner works with Task Force (TF) to draft a PR
   - Includes any research and analysis needed to get initial agreement
6. **TF Approval** - After TF approves, maintainers agree on next steps (usually member review)
7. **Concern Resolution** - If there are potential concerns outside the TF:
   - Maintainers get involved and drive to closure
   - Goal: full agreement to some scoped version, or at least no blocking pushback
8. **Member Review** - Final draft is presented for member review
9. **Merge** - If no blockers after 2-week review period:
   - PR is approved and merged
   - Can be implicit approval if no blockers

## Key Roles

- **Maintainers** - Prioritize, select features, resolve concerns, approve
- **FOCUS PM** - Assigns owners to feature requests
- **Owner** - Drives the feature through the process, works with TF
- **Task Force (TF)** - Working group that drafts and refines proposals
- **Members** - Broader group that reviews and can raise blockers
